Wireshark 抓包实战：过滤器编写、数据包捕获与 Web 异常定位

Wireshark 的实战价值不在于“能看到多少包”，而在于能不能快速从海量流量里找到异常证据。抓包实战要抓住三条主线：抓包前先设计捕获条件，过滤器分层缩小范围，定位时用对比和时序还原异常。三者咬合，才能从“看包”走向“断案”。

一、捕获前设计：先想清楚要抓什么

抓包最常见的错误是“先抓全量，回头再筛”。全量抓包文件巨大、噪声多，关键包容易被淹没。实战中先明确问题现象：是页面打不开、接口超时、上传失败、登录异常，还是偶发卡顿。再确定抓包位置：客户端本机、网关、负载均衡、应用服务器还是容器网卡。位置不同，看到的流量不同，NAT、代理和 TLS 终止都会改变包的特征。

捕获过滤器要在抓包前设置：按主机、网段、端口或协议限定范围，比如只抓某台客户端与某台服务器的交互，只抓 HTTP/HTTPS 或 DNS 流量。无线环境要选对网卡和监听模式，容器环境要确认抓的是宿主网卡、网桥还是 Pod 网卡。抓包时长和文件滚动要提前设好，避免磁盘写满。HTTPS 场景要提前准备密钥日志或确认可解密的链路位置，否则只能看到加密记录，无法分析 HTTP 语义。抓包前还要记录时间、操作步骤和复现条件，否则抓到包也难复现。

二、过滤器编写：捕获过滤与显示过滤分层用

Wireshark 有两类过滤器，职责不同。捕获过滤器在抓包时生效，语法更严格，用于减少写入量；显示过滤器在抓包后生效，语法灵活，用于分析定位。实战中先用捕获过滤器圈定范围，再用显示过滤器层层聚焦。

显示过滤建议按“会话—协议—异常”三层推进。第一层看会话：按 IP 对、端口或 TCP 流过滤，先确认连接是否建立、是否有 RST、是否重传。第二层看协议：聚焦 HTTP 请求响应、DNS 解析、TLS 握手，检查状态码、响应时间、Content-Type 和重定向。第三层看异常：过滤重传、乱序、零窗口、超时、ICMP 不可达和 TLS 告警。常用组合包括按请求方法、域名、URI 关键字、响应码和 TCP 标志位筛选。过滤表达式要保存成常用模板，团队共享，避免每次重写。分析时善用“跟随 TCP 流”和“专家信息”，前者还原完整会话，后者快速暴露重传、丢包和协议错误。

三、Web 异常定位：用对比和时序还原问题

Web 异常定位的核心是“对比正常与异常”。先抓一次正常请求作为基线，再抓异常请求，对比 DNS 解析时间、TCP 建连时间、TLS 握手时间、首字节时间和内容传输时间。如果 DNS 慢，查解析服务器和缓存；如果建连慢，查网络可达性和防火墙；如果 TLS 握手失败，查证书链、协议版本和 SNI；如果首字节慢，问题多在服务端处理；如果传输慢，查带宽、丢包和窗口大小。

常见异常有明确特征：大量重传和重复 ACK 提示链路丢包；零窗口提示接收端处理不过来；RST 频繁出现可能是连接被中间设备重置或服务端拒绝；HTTP 5xx 要看服务端日志配合；重定向循环看 Location 和 Cookie；接口超时要区分客户端等待、服务端未响应和响应未到达。对偶发问题，用时间序列看请求间隔、并发连接数和失败分布，判断是否与峰值、定时任务或特定节点相关。抓包结论要和应用日志、网关日志、监控指标交叉验证，单凭抓包容易误判。

最后，抓包文件要按问题编号归档，附上过滤表达式、时间线和初步结论，形成可复用的排查案例库。Wireshark 实战的心法是：抓之前想清楚，过滤时分层次，定位时做对比。做到这三点，抓包才能从“看热闹”变成“找证据”。
